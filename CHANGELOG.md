## [0.3.3] - 2026-11-22

Исправления по углублённому внутреннему аудиту 0.3.2 (H1, H2, M7, L2, L3, L4, L9). Протокол не менялся.

### Security
- Фильтр ответа блокирует ответ только по точным значениям секрета. Раньше любая строка вида
  `<цифры>:<30+ символов>` (или `ghp_...`) в ответе upstream, например в чужом сообщении, давала 502
  навсегда: `getUpdates` не сдвигал offset, и бот переставал получать обновления (H1).
- Шаблон токена без якоря давал квадратичное время на длинных цифровых строках и выполнялся в event
  loop. Шаблон убран из фильтра ответа, сам фильтр теперь работает в отдельном потоке (H2).
- Предпросмотр подтверждения маскирует только первые 2 КБ тела (раньше весь мегабайт), а шаблон PEM в
  `redact_text` ограничен по длине и не пересекает маркер `-----`: время линейное (M7).
- `[confirm] apis` сравнивается без учёта регистра: правило `POST:sendmessage` больше не обходит
  подтверждение для `sendMessage` (L2).
- `upstream_tls = false` разрешён только при `upstream_host` на loopback: иначе шлюз не запускается,
  токен не уйдёт по сети открытым текстом (L4).

### Fixed
- Проверки форматов используют `fullmatch`, а не `match` с `$`, который пропускал завершающий `\n`:
  id клиента, nonce, метод, путь, отпечаток, подпись, токены провайдеров, `file_path`, отпечаток
  приманки (L3).
- Сокет метрик удаляется при старте и остановке, только если по этому пути лежит сокет. Если там
  обычный файл, шлюз не запускается с понятной ошибкой (L9).

### Changed
- Токеноподобная строка в ответе upstream, не совпадающая с токеном шлюза, больше не блокирует ответ.
  Журнал по-прежнему маскирует такие строки.

### Tests
- `tests/unit/test_hardening_033.py`: регрессионные тесты H1, H2, M7, L2, L3, L4, L9.

### Известные открытые замечания аудита 0.3.2
- M1 (продление серверного сертификата), M2 (предпросмотр подтверждения), M3 (порядок записи в журнал
  и изменения состояния), M4 (ротация журнала, лимит записей об отказах), M5 и B-02 (оборванная строка
  журнала), M6, L1, L5, L6, L7, L8, L10. Запланированы на 0.3.4 и позже.

## [0.3.2] - 2026-11-22

Исправления по внутреннему аудиту 0.3.1 (замечания B-01, B-03, B-05, B-11). Критических и высоких
уязвимостей аудит не нашёл.

### Security
- Права `clients.json` проверяются при старте шлюза и в `gatekeeper status`: файл с `master_secret`
  не должен быть доступен группе и остальным, быть обычным файлом и принадлежать пользователю
  службы. Иначе шлюз не запускается (B-11).
- Файлы `clients.json`, `approvals.json` и `decoys.json` пишутся с fsync каталога после rename:
  `revoke`, `freeze` и `add-client` не откатываются при потере питания (B-05).

### Fixed
- `add-client` проверяет `--allow` тем же разбором, что и шлюз (`policy.parse_rule`): правила вида
  `DELETE:x` или `POST:123abc` отклоняются сразу, а не делают клиента «неизвестным» (403) уже после
  выдачи пакета (B-03).
- `gatekeeper status` показывает клиентов, чьи записи шлюз не сможет разобрать (B-03).

### Documentation
- SECURITY.md: описано реальное поведение состояния (SQLite, переживает перезапуск) и переполнения
  nonce-кэша (новые nonce отклоняются, не вытесняются) (B-01).
- README: провайдер GitHub, процедура ручного восстановления журнала с оборванным хвостом, список
  известных проблем. Модель угроз обновлена.
- Заполнены разделы 0.1.0 и 0.2.0 (B-16).

### Известные открытые замечания аудита
- B-02: журнал с недописанной последней строкой блокирует запуск и все запросы до ручной правки.
- B-04: записи SQLite выполняются в event loop (не измерено под нагрузкой).
- B-06, B-07, B-13: actions не закреплены по SHA, нет проверки свежести lock и lock для dev-инструментов.
- B-08, B-09, B-10, B-12, B-14, B-15, B-17: гигиена и устойчивость к повреждённым данным.

## [0.3.1] - 2026-11-22

### Changed
- Тестовый TLS-клиент явно требует TLS не ниже 1.2 (закрывает 3 предупреждения CodeQL «Use of insecure SSL/TLS version» в тестах; на шлюз не влияет).

## [0.3.0] - 2026-11-22

### Added
- Group commit журнала: один fsync на пачку одновременных записей.
- `state.db` (SQLite, WAL): nonce, суточный бюджет, баны и счётчики аномалий переживают перезапуск.
- `X-Request-Id` в каждом ответе и `rid` в записях журнала; `Date`, `Cache-Control: no-store`;
  `Retry-After` в ответах 429.
- `[server] metrics_socket`: `GET /healthz` и `GET /metrics` на Unix-сокете.
- `gatekeeper status`.
- Лимит nonce на клиента (один клиент не заполняет весь кэш), LRU-границы для лимитеров и банов.
- `py.typed`, `readme` и `[project.urls]` в pyproject, CI с матрицей 3.11–3.14, ruff, mypy, pip-audit, CodeQL, Dependabot.

### Changed
- `license` в pyproject: SPDX-строка; убран устаревший classifier.
- systemd-юнит: `MemoryDenyWriteExecute`, `ProtectProc`, `ProcSubset`, `StartLimitBurst`, `AF_UNIX`.
- mypy: 0 ошибок в `src`.
- h11>=0.16 (в более ранних версиях неточный разбор chunked-тел, CVE-2025-43859).
- Dependabot: `increase-if-necessary`, чтобы не поднимать нижние границы без нужды.
- CI: `pip-audit` проверяет `requirements.lock`.

## [0.2.0] - 2026-11-19

### Added
- Провайдер GitHub REST API (`[provider] name = "github"`): методы `getUser`, `listRepos`,
  `listNotifications`, `getRateLimit` (только GET, без тела); токен подставляется шлюзом в заголовок
  `Authorization`. Один провайдер на экземпляр шлюза.
- Внешние якоря журнала: `gatekeeper audit-anchor` и `audit-verify --anchors`.
- Автозаморозка клиента по аномалиям (`[anomaly]`, по умолчанию выключена).
- Подтверждение опасных действий (`[confirm]`, `gatekeeper pending/approve/reject`, по умолчанию выключено).

### Changed
- При остановке шлюз отслеживает и отменяет незавершённые задачи соединений.
- README переписан под универсальный шлюз, обновлена модель угроз.

## [0.1.0] - 2026-11-06

Первый релиз: шлюз для Telegram Bot API. mTLS (TLS 1.3) и HMAC-подпись каждого запроса, белый список
«метод + путь» на клиента, журнал с цепочкой хешей, приманки, фильтр ответов upstream, лимиты.

### Fixed
- Явный лимит глубины JSON в фильтре ответа (отказ вместо `RecursionError`).
- Имя API в политике разбирается через `fullmatch`.
